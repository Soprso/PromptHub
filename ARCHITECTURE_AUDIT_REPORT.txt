2. IMAGE STORAGE INVESTIGATION
================================================================================

IMAGE FILE STORAGE: Cloudflare R2

Storage Provider Details:
  - Provider: Cloudflare R2
  - Access method: @aws-sdk/client-s3 with R2 endpoint
  - Endpoint: https://{accountId}.r2.cloudflarestorage.com
  - Region: 'auto'

R2 Environment Variables (from netlify/functions/upload-image.ts):
  - R2_ACCOUNT_ID: Cloudflare account ID
  - R2_ACCESS_KEY_ID: R2 access key
  - R2_SECRET_ACCESS_KEY: R2 secret key
  - R2_BUCKET_NAME: R2 bucket name
  - VITE_R2_PUBLIC_URL: Public URL base for generating R2 URLs

Image Upload Workflow:
  1. Admin selects file in SubmitImagePage.tsx
  2. r2Upload(file) → fetch('/api/upload-image') → Netlify Function
  3. upload-image.ts parses multipart form data
  4. Uploads to R2 via PutObjectCommand
  5. Generates filename: image-of-day-{timestamp}-{random}.{ext}
  6. Returns URL: {VITE_R2_PUBLIC_URL}/{filename}
  7. URL stored in CockroachDB image_of_day.image_url

Image Characteristics:
  - Allowed types: PNG, JPEG, WebP
  - Max size: 5MB
  - No BLOB/base64 storage in database
  - Only URLs/keys stored in CockroachDB

Legacy Storage (no longer active):
  - scripts/seed-data.json: Contains old Supabase URLs
    (zxqyabfvzkkgisiapmpc.supabase.co/storage/v1/object/public/image_of_day/)
  - supabase_schema.sql, supabase_community_schema.sql: Legacy schemas
  - These are historical references only; active code does not use Supabase Storage

3. IMAGE LOADING WORKFLOW
================================================================================

COMPLETE WORKFLOW: From Database to Browser

STEP 1: Image Records Retrieved from Database
  - Function: imageOfDayApi.getPaginatedImages()
  - API: GET /api/image-of-day?type=paginated&page=1&limit=10
  - Netlify Function: image-of-day.ts
  - DB Query: SELECT * FROM image_of_day WHERE is_active = true ORDER BY created_at DESC
  - Result: JSON with ImageOfDay objects containing image_url fields

STEP 2: API Endpoint that Fetches Image Information
  - Endpoint: GET /api/image-of-day?type={featured|latest|paginated|search}
  - Function: netlify/functions/image-of-day.ts
  - Parameters: type, page, limit, query, searchQuery
  - Response: { data: [{id, image_url, prompt, likes, created_at, is_active}], count: number }

STEP 3: How Image URLs Are Generated
  - During upload (SubmitImagePage.tsx → r2Upload → upload-image.ts):
    • File uploaded to Cloudflare R2
    • Generated filename: image-of-day-{timestamp}-{random}.{ext}
    • URL format: {VITE_R2_PUBLIC_URL}/{filename}
    • Example: https://promptshub.r2.dev/image-of-day-1730234567890-abcd1234.png
  - URL stored in CockroachDB image_of_day.image_url column

STEP 4: Frontend Loading (Direct from Storage Provider)
  - <img src={item.image_url} loading="lazy" alt={...} />
  - No backend proxy - images loaded directly from R2 CDN
  - image_url from DB used directly as src attribute
  - Two main image components use this pattern:
    * ImageOfDayCard.tsx (line 108): iod-image-${item.id}
    * ImageCarousel.tsx (line 103): carousel-image-card

STEP 5: Caching Mechanism
  - R2 Side: Cache-Control: public, max-age=31536000, immutable (set in upload-image.ts:55)
  - Browser Side: Standard HTTP cache control
  - No frontend caching layer beyond browser HTTP cache
  - Permanent caching due to "immutable" directive

STEP 6: Lazy Loading
  - loading="lazy" attribute on all <img> elements
  - ImageOfDayCard.tsx:110: loading="lazy"
  - ImageCarousel.tsx:105: loading="lazy"
  - Images load only when scrolled into viewport

STEP 7: Error Handling
  - If image fails to load: No special fallback in <img> elements
  - Alt text provides descriptive context
  - ImageModal.tsx shows default shadow styling on error
  - No retry logic in current implementation

|-----------|----------------------|

| Supabase Usage | None in active code (intentionally migrated away) |

6. RECOMMENDATIONS
================================================================================

CURRENT ARCHITECTURE ASSESSMENT: ✅ Efficient and well-designed

STRENGTHS:
1. Clean separation of concerns: CockroachDB for metadata, R2 for storage, Netlify Functions for API
2. No database BLOBs: Images never stored in database - only URLs, saving space and improving performance
3. CDN delivery: R2 provides automatic CDN distribution with global edge caching
4. Lazy loading: loading="lazy" on all images improves initial page load performance
5. Proper caching: Cache-Control: immutable on R2 assets ensures long cache times
6. Migration complete: Supabase fully replaced with CockroachDB + R2
7. No Neon PostgreSQL usage - using CockroachDB which is PostgreSQL-compatible but distributed

POTENTIAL OPTIMIZATIONS:
1. Image CDN transformations: Could add Cloudflare Images for automatic format optimization (WebP/AVIF), resizing, and dynamic transformations
2. Image preloading: Consider preloading hero/image above-the-fold images for critical above-the-fold content
3. Server-side image optimization: Could add a resize/proxy function for dynamic image dimensions without re-upload
4. Database query optimization: image-of-day queries could benefit from indexing on (is_active, created_at) - likely already optimized given small table size

UNNECESSARY DATABASE CALLS: None identified - architecture avoids database calls for image delivery (images come directly from R2 CDN)

PERFORMANCE BOTTLENECKS:
- Primary bottleneck would be CockroachDB query latency for fetching image lists, but given the small dataset (likely < 100 active images), this is negligible
- Network latency to R2 CDN is minimal due to Cloudflare's global edge network
- Current architecture is well-optimized for the use case

MIGRATION PATH CONSIDERATION:
- Current architecture (CockroachDB + R2) is already optimized
- No need to migrate unless requiring built-in image transformation features
- Would require adding Cloudflare Images or dedicated CDN service for those features

7. COMPLETE ARCHITECTURE: FROM DATABASE TO BROWSER
================================================================================

IMAGE STORAGE ARCHITECTURE:

1. ADMIN UPLOADS IMAGE:
   - File → r2Upload() → /api/upload-image Netlify Function → Cloudflare R2
   - R2 stores file with key: image-of-day-{timestamp}-{random}.{ext}
   - R2 returns public URL: {VITE_R2_PUBLIC_URL}/{filename}
   - URL stored in CockroachDB image_of_day.image_url column

2. PAGE LOADS IMAGES:
   - imageOfDayApi.getPaginatedImages() → fetch('/api/image-of-day?type=paginated...')
   - netlify/functions/image-of-day.ts → SELECT * FROM image_of_day WHERE is_active = true ORDER BY created_at DESC → CockroachDB
   - JSON returned with image_url fields containing R2 CDN URLs
   - Frontend maps over results and renders <img src={url} loading="lazy" />

3. BROWSER RENDERS:
   - <img src="https://promptshub.r2.dev/image-of-day-1234567890-abcd1234.png" loading="lazy" />
   - Image loads directly from Cloudflare's global edge CDN
   - Cache-Control: public, max-age=31536000, immutable header ensures browser caching
   - loading="lazy" defers loading until image scrolls into viewport

KEY TECHNOLOGY STACK:
- Database: CockroachDB (PostgreSQL-compatible) - stores metadata only
- Image storage: Cloudflare R2 - stores actual image files
- API layer: Netlify Functions (esbuild) - mediates between frontend and database/storage
- Frontend: React 19 + Vite - loads images directly from R2 CDN with lazy loading
- No Supabase in production code: Intentionally migrated away (src/lib/supabase.ts exports null)
